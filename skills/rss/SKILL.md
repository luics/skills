---
name: rss
description: Fetch and manage local RSS/Atom subscriptions stored in feeds.json, including HTML email reports.
---

Run the bundled `scripts/rss.mjs` with the working directory set to the local RSS workspace that contains `feeds.json`. The scripts keep only feed definitions and cursors; do not create or use a post/article store.

```bash
node <skill>/scripts/rss.mjs [--feeds <absolute-path>] [fetch] [scope ...] [--limit <count>] [--dry-run] [--markdown|--html|--json]
node <skill>/scripts/rss.mjs feed list [--json]
node <skill>/scripts/rss.mjs feed add --id <id> --name <name> --url <RSS/Atom URL>
node <skill>/scripts/rss.mjs feed update <id|URL> [--id <id>] [--name <name>] [--url <RSS/Atom URL>] [--lastest-article-at <ISO-UTC>] [--disabled <true|false>]
node <skill>/scripts/rss.mjs feed remove <id|URL> --confirm
node <skill>/scripts/rss.mjs sendmail [scope ...] [--debug[=true|false]|--no-debug] [--output-html <path>]
```

`fetch` is the default command. By default the scripts use `feeds.json` in the working directory; use `--feeds` when the file is elsewhere. Use `--dry-run` to fetch and render without advancing cursors. A scope is either an exact feed URL or a case-insensitive keyword matched against id, name, or URL. Process every matched feed once; report unmatched scopes without stopping other feeds. Do not request article pages: use only RSS/Atom content.

Treat a missing or blank `lastestArticleAt` as `1970-01-01T00:00:00Z`. Output only entries later than that cursor. After a successful feed fetch, advance its cursor to the latest newly fetched article, even when output is limited. Do not advance a failed feed. A feed with `disabled: true` must not be fetched; a missing or `false` value is enabled.

Without an explicit `--limit`, limit each first-time feed (missing/blank or Unix-epoch cursor) to its 10 newest articles; subsequent fetches return all new articles without a limit. Evaluate this per feed using its cursor before fetching, including during `sendmail`. An explicit positive `--limit` overrides the automatic policy.

For batch translation, send and receive compact arrays shaped `[[feed_id, feed_name, [[title, description], ...]], ...]`. Codex structured output uses `--output-schema` with a root `{ "feeds": [...] }` wrapper around the same compact array; unwrap it before validation. Input contains only these fields; omit URLs, dates, and counts, and restore article metadata locally. Translate full titles faithfully and produce factual Simplified-Chinese summaries of nonempty descriptions, targeting about 140 Unicode code points including punctuation; slightly longer summaries are acceptable and must not cause rejection or local clipping. Keep empty descriptions empty. Validate array shapes, ids/order, article counts, and description types/empty values before applying the batch; When strict JSON parsing fails, normalize typographic string delimiters while preserving quotation marks within text, then validate normally. Other invalid output falls back to original text without another translation request.

For conversational output, group feeds that have new entries with Markdown H2 headings. Render every title as `[MM.dd] article title` (with the title linked), omit a missing description, and summarize a description longer than 140 words or Chinese characters. Use `--html` for a self-contained email-friendly report or `--json` when another tool needs raw article metadata.

HTML reports declare support for light/dark color schemes and use `prefers-color-scheme: dark` to adapt all report sections to the system theme. Clients without media-query support receive the light palette.

Do not render a separate “状态” section. Show unmatched scopes and fetch errors inside “调试信息” when debug is enabled. Append disabled feeds to the end of its subscription table using `⚠️title` and `-` in all five remaining columns. Disabled feeds are excluded from timing allocation and hotspots.

All runtime log lines use a UTC ISO 8601 prefix (`[YYYY-MM-DDTHH:mm:ss.sssZ]`), including warnings, errors, stack traces, and sendmail subprocess output. JSON, HTML, Markdown reports, feed tables, and help output retain their data formats without log prefixes.

The debug total-time row includes its breakdown in the same line: `总耗时（截至提交前）：x.xs（拉取 x.xs；翻译 x.xs；渲染正文 x.xxxs）`. All debug durations use one decimal place except body rendering, which uses three. Label an unexecuted stage “未执行” rather than reporting zero duration.

Subscription-table durations are seconds displayed as bare numbers with one decimal place (for example, `0.7`), without the `s` suffix. Total-time and hotspot text retain the suffix.

`--output-html <path>` (or `--output-html=<path>`) optionally saves the final email HTML as UTF-8 before delivery, including debug information when enabled. It is disabled by default and also works with `DRY_RUN=1`. Relative paths resolve against the working directory; the parent directory must exist. An existing file is overwritten, and a write failure stops delivery. Supported by both `rss.mjs sendmail` and direct `rss-mailer.mjs` invocation.

The mailer enables `--debug` by default. A separate final “调试信息” section includes article/failure/fallback counts, one “总耗时（截至提交前）” row, a nested “耗时热点：” list, then a “订阅源” table with columns `title`, `实拉`, `平拉`, `翻译`, `累计`, `报告`. Display only the report count when it equals the discovered count; otherwise display `report_count/discovered_count` in the report column. Prefix titles with ✅, or ❌ when fetching/translation failed or timed out. Overall debug fetch duration spans the first feed fetch start through completion of all feed fetches, excluding process startup and cursor persistence. `实拉` is the actual per-feed duration; `平拉` is overall fetch duration divided by attempted feeds (including failures, excluding disabled feeds). Allocate total batch translation duration in proportion to each reporting feed’s source Unicode code point count (feed name plus reported article titles and descriptions, excluding ids and JSON syntax); zero-report feeds receive no allocation and display “-”. `累计 = 平拉 + 翻译`; the slowest-feed hotspot uses this same allocation. Keep the caption simply “订阅源” without allocation explanations. Failed fetches show “—” for unknown article counts. Hotspots use separate list items. Omit “日志总结”, a separate stage-duration row, and double-counting explanations. `--debug=false`, `--debug false`, or `--no-debug` omits this section. The email's total is sampled before generating the final debug summary and submission; complete total and submission duration remain in runtime logs.

Every `sendmail` run logs timing events to stderr with a shared `run_id`: `total`, `fetch`, `fetch_feed`, `translate`, `render`, and `sendmail`. There are no per-feed translation requests or timing events. Stages emit `event=start` and `event=end`; end events include `status` and monotonic `duration_ms` to one decimal place. Feed events include `feed_id`. The `fetch` log additionally includes subprocess and JSON parsing overhead; the debug report uses the feed batch's wall time. Total summaries record `outcome` (`queued`, `dry_run`, or `failed`), fallback/failure counts, discovered `new_articles`, and limited `report_articles`. Failed/timed-out work retains elapsed time; unexecuted stages emit no events. `sendmail` measures MIME construction through local process closure, not inbox delivery. Capture both streams (for example, `2>&1 | tee -a rss-sendmail.log`) for persistent logs.

Fetching uses at most three concurrent feed workers. Keep results in subscription order and persist successful cursors once after all workers finish; one failed feed must not stop others. `sendmail` invokes `scripts/rss-mailer.mjs`, collects all fetch results, then issues exactly one local `codex exec` request containing every feed with reported articles. Validate batch feed ids/order/count and all article counts before applying any translation. Batch failure or timeout preserves original text for every included feed and records their fallback count. Empty feeds do not enter translation; when no articles are reported, skip translation but still send the empty/status report. Translation defaults to `gpt-6-luna` with `model_reasoning_effort="none"`; set `CODEX_TRANSLATION_MODEL` to override the model. `CODEX_TRANSLATION_TIMEOUT_MS` is the whole-batch timeout (default 120000). Configure delivery with `MAIL_TO`, `MAIL_FROM`, `REPORT_TIMEZONE`, `MAIL_SUBJECT_PREFIX`, and optional `SENDMAIL_PATH`; `CODEX_EXECUTABLE` overrides `codex`. `DRY_RUN=1` prevents delivery. Adding a feed initializes its cursor to the epoch; validate HTTP(S) URLs and unique ids/URLs. Deletion requires `--confirm`.
